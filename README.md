# 杂交稻制种受托与授权

协调杂交稻品种授权、制种受托、田块排程和批次交付，防止同一块制种田在重叠农时被重复承诺，并让减产责任可沿实际依赖重算、可追溯。

## 领域范围

系统涉及种业企业、制种受托人、县域管理人员、独立检验人员。领域关注：

- 制种区域覆盖多个县并承接大量水稻品种
- 行业发布制种价格指数和受托人分级制度
- 品种评价同时关注产量、品质、抗逆与适应性

## 制种委托服务

`src/hybrid_rice_seed_trustee/` 实现一个**事件溯源（event-sourced）**的制种委托服务。系统唯一的事实来源是仅追加的事件流；所有当前状态都由重放得到，服务对象不持有可变状态，因此进程停机恢复后，尚未到期的农时、复检、结算与补种工作不会丢失。

模块划分：

- `events.py`：领域事件定义（带业务幂等键）
- `store.py`：JSON Lines 仅追加存储，追加即落盘（fsync），容忍停机造成的尾部残行
- `ledger.py`：事件流重放，派生出田块窗口、版本化的受托等级与品种授权、亲本批次、价格指数、合同计划版本、种子批次与工作项
- `service.py`：全部业务裁决

### 业务规则如何落地

- **合同成立判定**：提案时按田块适播窗口、隔离距离与适宜品种、受托人当时等级版本与单季能力、亲本批次余量与适用区域、品种授权（按当时有效版本）逐项判定，不成立也留痕全部原因。
- **唯一争用安排**：争用以“同一块田 + 实际播种窗口重叠”聚类，依据已发布的公开优先规则版本（申请在先/受托等级/连片面积，申请时间兜底保证唯一）裁决；受托能力或亲本余量不足时由簇内下一候选递补。已有生效合同受保护，只有经复核的越级调整才能替代，且已播种部分绝不能被随后调度改写。
- **计划版本固化**：合同成立时把适宜区域、隔离要求、目标面积、结算期间、价格指数版本、受托等级版本、授权文号、优先规则版本一并快照进计划 v1；后续修订生成新版本，已播种面积锁定，隔离要求与适宜区域在播种后不可改。
- **生产事实**：播种、花期、去杂、检验、交种按来源与报送编号追加；同一报送重试幂等忽略，结论一致的重复报送只确认原结论（不改写），结论矛盾则双方记录都保留、冻结相关批次并交**与原报送来源无关的独立检验人员**复核（解冻或判废）。
- **沿依赖重算**：灾害（可按县/田块/合同/亲本或种子批次定界，多合同时按目标面积分摊）、授权撤回、检验不合格或复核判废后，沿“合同→计划固化版本→亲本/种子批次”重算可交付数量、补种责任人和补种期限；已完成交接的证据独立保留，授权撤回后未交接部分不得再交种。
- **价格指数按期间适用**：每个指数版本自带明确适用期间，签约时固化；新版本不向前改写既有计划或已完成结算，只有适用期间明确覆盖结算期间的版本才能经计划修订显式采用。
- **越级调整双人复核**：越级申请须由一名县域管理人员发起、**另一名**管理人员复核，全程留痕；未获批的提案在裁决中仍按公开规则落选。
- **批次可解释**：`explain_batch` 可解释任一种子批次的授权（计划固化版本与当前版本）、田间过程（播种/花期/去杂/检验/交种）、合同时点与当前受托等级、冻结复核记录及最终去向。
- **到期工作持久化**：适播截止、花期检查、结算截止、不合格复检、补种责任都是事件流中的工作项，重启后用 `due_work` 即可取回。

## 目录说明

- `contracts/domain.schema.json`：静态领域资料结构
- `fixtures/domain.json`：不含真实身份信息的示例资料
- `src/hybrid_rice_seed_trustee/context.py`：读取并检查静态领域资料
- `tests/`：`test_context.py` 校验资料读取，`test_service.py` 覆盖上述全部规则及停机恢复

## 开发命令

- 运行测试：`python3 -m unittest discover -s tests -v`
- 编译检查：`python3 -m compileall -q src`

上述命令只读取仓库内资料，不需要连接外部业务服务。
