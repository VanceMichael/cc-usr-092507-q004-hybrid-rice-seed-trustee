# 杂交稻制种受托与授权

协调杂交稻品种授权、制种受托、田块排程和批次交付，解决多家企业在重叠农时
争用同一块制种田、减产之后各方拿不同版本资料互相推责的问题。

## 领域范围

系统涉及种业企业、制种受托人、县域管理人员、独立检验人员。业务事实：

- 制种区域覆盖多个县并承接大量水稻品种
- 行业发布制种价格指数和受托人分级制度
- 品种评价同时关注产量、品质、抗逆与适应性
- 同一制种田可能在重叠农时被多家企业承诺
- 播种、花期、去杂、检验、交种事实由不同来源报送

## 制种委托服务规则

实现见 `src/hybrid_rice_seed_trustee/service.py`，所有状态变化都先表达为
不可变事实并追加进只增日志（事件溯源），状态由日志回放得到。

### 1. 合同成立判断

提案评审必须同时满足，任一不满足则合同不成立（记录 `PLAN_REJECTED`）：

- 评审日存在有效的**品种授权版本**且未撤回，田块位于授权适宜区域
- 田块可保证的空间隔离距离不低于授权要求
- 受托人在评审日有有效的**等级版本**，等级不低于授权要求
- 受托人当季累计承诺面积不超过其等级对应的能力上限
- 排程窗口落在田块可用农时窗口内
- **亲本批次**存在、品种一致且余量充足
- 存在明确标注该**结算期间**的价格指数版本，且含该品种单价

合同成立当时把适宜区域、隔离要求、目标面积、结算口径（价格指数版本与
结算期间）、规则簿版本固化进计划快照（`PLAN_CONFIRMED`）。之后发布的
授权、等级、指数新版本都不回溯改写快照。

### 2. 唯一安排（争用仲裁）

重叠农时争用同一块田、或同一受托人当季能力/同一亲本批次余量不足时：

- 依据仲裁日已发布的**公开规则簿版本**中的优先键顺序全局排序
  （可用键：等级、提案先后、目标面积、企业/受托人、计划号兜底），
  按优先级从高到低贪心裁定；
- 真正冲突时一个争用点只有一个赢家，输家记录 `lost_arbitration`
  及所适用的规则簿版本；
- 互不冲突（农时不重叠、能力与亲本充足）的计划可以共存。

### 3. 计划版本固化与播种锁定

- 普通调度（`PLAN_RESCHEDULED`）只能改写**未播种余量**；
- 已播种田块的窗口与面积被锁定：新排程必须覆盖原窗口、面积不得低于
  已播种面积；
- 越级调整（`PLAN_OVERRIDE`）不直接生效，必须由**另一名管理者**复核：
  通过后才写入新版本（`OVERRIDE_APPROVED`），驳回则计划不变；提案人、
  复核人、时间与理由全部留痕。

### 4. 田间事实：追加、去重与冻结

- 播种、花期、去杂、检验、交种按（来源，来源方报送编号）追加；
- **同源同号重复报送**直接返回原结论，不产生新事实；
- 异源结论矛盾（如两次检验一合格一不合格）时追加矛盾事实并
  **冻结批次**（`DISCREPANCY_FROZEN`），登记独立复核到期任务，
  冻结期间停止接收新报送；
- 独立检验人员复核（`REVIEW_RESOLVED`）：合格解冻，不合格否决批次。

### 5. 灾害、撤回、不合格的依赖重算

灾害、授权撤回、检验不合格/复核结论发生后，沿
**亲本批次 → 计划 → 生产批次**的实际依赖重新计算：

- 灾害损失先冲减在田未冻结播种面积（产生补种责任），超出部分冲减未播排程；
- 授权撤回后未交付部分不再具备交付依据，已完成交接的证据与数量保留；
- 检验不合格先冻结对应在田面积，复核后按结论恢复或否决；
- 补种亲本余量不足时，沿亲本批次依赖列出其他受影响合同；
- 重算结果以 `RECOMPUTATION` 事实留存，每次都从全部事实直接推导，
  同一触发重复执行结论一致。

### 6. 结算口径与价格指数期间

- 价格指数的每个新版本必须显式标注其适用结算期间与日期范围；
- 结算严格使用合同成立快照中固化的指数版本，新版本只进入其明确适用的
  期间，不回溯进入旧期间或已固化的合同；
- 交种日必须落在固化指数的期间日期范围内，否则不能结算；
- 结算线一经固化（`SETTLEMENT_FINALIZED`）不可变、不可重复结算。

### 7. 批次追溯与停机恢复

- `trace_batch` 可解释一个种子批次的授权版本、田间全过程（播种/花期/
  去杂/检验）、成立时受托人等级、冻结与复核记录、最终去向与交接证据；
- 农时窗口到期、复检、独立复核、结算都登记为到期任务；
- 日志写入即 `fsync`，进程重启后重放全部事实，尚未到期的农时、复检
  与结算工作以及全部业务状态不丢失。

## 模块地图

| 文件 | 职责 |
| --- | --- |
| `context.py` | 读取并校验领域资料 |
| `models.py` | 事实类型、计划快照、到期任务、批次状态等值对象 |
| `journal.py` | 只增事实日志（落盘 fsync，停机不丢） |
| `state.py` | 日志回放投影：版本资料、田块占用、计划、批次、任务 |
| `service.py` | 全部领域规则：合同成立、仲裁、调度、报送、重算、结算 |
| `contracts/domain.schema.json` | 领域资料结构 |
| `fixtures/domain.json` | 不含真实身份信息的示例资料 |
| `tests/` | `test_context.py` 资料校验；`test_service.py` 44 个领域规则测试 |

## 开发命令

- 运行测试：`python3 -m unittest discover -s tests -v`
- 编译检查：`python3 -m compileall -q src`

上述命令只读写仓库内资料与临时日志，不需要连接外部业务服务。
